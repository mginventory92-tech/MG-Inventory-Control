# معمارية MG Material Control

## الصورة الكبيرة
```
المتصفح (React، GitHub Pages)
   │  1) تسجيل الدخول: Supabase Auth
   │  2) كل العمليات:   POST /rest/v1/rpc/api   ← دالة واحدة public.api(method, path, query, body)
   │  3) إدارة المستخدمين: POST /functions/v1/users  ← Edge Function (بصلاحية service role)
   ▼
Supabase (Postgres)
   ├─ public.api            الباب الوحيد المفتوح للمستخدمين المسجّلين (security definer)
   ├─ private.*             الراوتر والدوال المساعدة (مش متاحة من برّه)
   └─ الجداول               مقفولة تمامًا: RLS مفعّل ومفيش policies ولا grants لـ anon/authenticated
```

## القرارات الأساسية
| القرار | السبب |
|---|---|
| الجداول مقفولة والتعامل كله عبر `public.api` | مفيش طريقة لقراءة أو كتابة بيانات إلا من خلال دالة بتتحقق من الصلاحيات على السيرفر، حتى لو المفتاح العام اتسرّب (وهو علني أصلًا) |
| منطق المخزون جوه قاعدة البيانات | الخصم من الرصيد في أمر واحد ذري (`update ... where qty >= الكمية`)، فمفيش رصيد سالب حتى مع عمليتين في نفس اللحظة، وترتيب ثابت للأصناف يمنع التعليق (deadlock) |
| الصلاحيات في `profiles.permissions` | 8 صلاحيات (`items, warehouses, in, out, transfer, parties, reports, users`)، والتحقق في SQL مش في الواجهة |
| إنشاء/حذف المستخدمين في Edge Function | لأن ده بيحتاج مفتاح الإدارة (service role) اللي مينفعش يوصل للمتصفح |
| اسم المستخدم = إيميل داخلي `اسم@mginv.example.com` | عشان الدخول باسم مستخدم من غير إيميل حقيقي |
| الواجهة بتنشر على فرع `gh-pages` تلقائيًا | بدون سيرفر ولا تكلفة استضافة |

## قواعد العمل
- **الـ migrations:** `supabase/migrations/NNN_*.sql` بالترتيب. الملف ما بيتعدّلش بعد تطبيقه، أي تغيير جديد = ملف جديد برقم أعلى. أول مدير بيتعمل من `supabase/seed/first_admin.sql`.
- **الأخطاء:** دوال SQL بترمي خطأ برسالة عربية وكود HTTP في `hint` (400/401/403/404/409)، والواجهة بتعرضها زي ما هي.
- **الحماية من الانحراف:** `web/tests/contract.test.ts` بيفشل لو الواجهة بتنده مسار مش موجود في SQL، أو قايمة الصلاحيات/دومين الإيميل اختلفوا بين الواجهة ودالة المستخدمين، أو جدول اتعمل من غير RLS.
- **اختبار حركة المخزون:** `supabase/tests/stock_flow.sql` بيتشغّل يدويًا من SQL Editor وبيخلص بـ rollback (مفيش بيانات بتتحفظ).
- **CI:** كل push بيعمل typecheck + اختبارات + build، وعلى `main` بينشر تلقائيًا.

## حدود معروفة
- `mobile/` (Flutter) لسه متوصّل بالباك إند القديم ومش شغال مع Supabase.
- الإذن بعد حفظه مش بيتعدّل ولا بيتلغي، وبيتصلّح بإذن عكسي.
- migration `004_refactor_documents.sql` (توحيد فلتر قايمة الإذون وإزالة الجدول المؤقت) جاهز ومتجرّب، ومحتاج تشغيله من SQL Editor في Supabase.
- بيئة واحدة فقط (إنتاج)، ومفيش بيئة تجريب.
- النسخ الاحتياطي والإيقاف التلقائي للمشاريع المجانية بيعتمدوا على خطة Supabase.
